## Что сделать

### П1. `h1` и строка «Streamed X ago» — под «Hide video titles»
- `src/content/content.js`, `VIDEO_TITLE_SELECTORS`: добавить `ytd-watch-metadata h1` и
  `ytd-watch-metadata ytd-watch-info-text` с комментарием (название открытого видео и строка под ним:
  просмотры, «Streamed X ago» / «15h ago», точная дата в подсказке и после «more»). Блюр 8px, как у остальных
  названий; клики не блокировать.
- Нативная подсказка `title` у `h1 yt-formatted-string` снимается уже существующим механизмом B15
  (`stashTitleAttribute` ищет `closest(VIDEO_TITLE_SELECTOR_LIST)`) — проверить тестом, что для элемента внутри
  `ytd-watch-metadata h1` атрибут уходит в `data-yas-title`.
- Допущение главной сессии: блюрится вся строка `ytd-watch-info-text` (вместе с числом просмотров и хэштегами) —
  дата в ней отдельным стабильным элементом не выделена (`#info` у записи эфира содержит и просмотры, и
  «Streamed…»).

### П2. «Show comments» для панели комментариев (`/watch`) и Shorts
Образец — `syncCommentsGuard` / `renderCommentsGuardOverlay` в `src/content/content.js:736–831`.
- **id видео для гарда**: на `/shorts/<id>` — этот `<id>`; иначе — как сейчас `shared.getLiveStartVideoId(root,
  doc)`. `getLiveStartVideoId` не менять (на нём держится защита эфиров). Решение «Show comments» — одно на
  видео / Short и действует сразу на комментарии под видео и на панель; на следующем видео или Short — снова
  скрыто (Shorts: листание стрелкой при открытой панели → новый id → панель снова закрыта).
- **Панель**: селектор `ytd-engagement-panel-section-list-renderer[target-id="engagement-panel-comments-section"]`
  (все такие панели в документе, скрытые тоже — их несколько после SPA).
  - CSS под тем же классом `html.yas-comments-obscured`: `PANEL #content` — `position: relative`;
    содержимое `PANEL #content > ytd-section-list-renderer` — `filter: blur(18px)`, `pointer-events: none`.
  - Оверлей «Comments hidden» + кнопка «Show comments» — дочерний элемент `PANEL #content` (не размывается,
    потому что блюр стоит на соседнем `ytd-section-list-renderer`), `position: absolute; inset: 0` — `#content`
    фиксированной высоты, прокручивается только внутренний `#contents`, поэтому оверлей закрывает всю видимую
    область. Шапка панели (заголовок, сортировка, Close) остаётся видимой и рабочей.
  - Вид оверлея и кнопки — как у текущего оверлея комментариев (те же правила CSS; без `position: sticky` у
    панели оверлея внутри панели не нужно, кнопку — сверху по центру).
- Оверлеев теперь может быть несколько (под видео + в каждой панели), поэтому: находить и удалять их по общему
  классу/атрибуту, а не только по `getElementById`; не вставлять второй оверлей в тот же хост. Существующий
  экспорт `COMMENTS_GUARD_OVERLAY_ID` и тесты под видео — сохранить работающими (можно оставить id у оверлея под
  видео, а панельным дать класс).
- Клик «Show comments» в любом оверлее — снимает все оверлеи и класс `yas-comments-obscured` для текущего видео.
- Выключение «Hide comments» или всей защиты — снимает все оверлеи (как сейчас).
- Проверка раз в секунду (`COMMENTS_GUARD_CHECK_MS`) уже есть — она же должна достраивать оверлей в панели,
  которую YouTube создал/перерисовал позже.
- Правило блюра для тизера `ytd-comments-entry-point-header-renderer` — оставить без изменений.

### П3. «Most replayed» — под «Blur previews»
- `content.js`, CSS: `html.yas-hide-video-previews .ytp-heat-map-container` — **скрыть** (`visibility: hidden`,
  `opacity: 0`, `pointer-events: none`), а не размыть: размытая кривая высотой 40px всё равно показывает, где
  пики. Комментарий в коде: пики «Most replayed» часто совпадают с голами/ключевыми моментами.
- Отдельным правилом рядом с превью (не добавлять в `VIDEO_PREVIEW_SELECTORS`, там блюр).

### П4. Кнопки перемотки не показываются, когда плеер запрещает перемотку
- `src/content/live-player-bridge.js` (MAIN world): функция, которая ставит на `#movie_player` атрибут
  `data-yas-seek-blocked`, когда `getPlayerCanRewind(player) === false`, и снимает его иначе (`true` или `null`).
  `toggleAttribute(name, force)` — без лишних мутаций, когда состояние не меняется. Вызывать раз в секунду из
  `initLivePlayerBridge` (`currentWindow.setInterval`, 1000 мс) — так мост сам следит за плеером, без нового
  события между мирами. Если в тестовом окне нет `setInterval` — не падать.
- `content.js`, CSS: правило показа кнопок
  (`html.yas-extension-enabled.yas-hide-player-progress-bar.yas-show-skip-buttons:not(.yas-live-start-obscured)
  #movie_player .yas-skip-buttons`) дополнить условием `#movie_player:not([data-yas-seek-blocked])`. Комментарий:
  эфир без DVR — плеер отказывает в перемотке, кнопки были бы мёртвыми.
- `skip-buttons.js` не трогать без нужды (логику `skipVideo` по `seekable` оставить).
